# SPEC 01 — BANCO DE DADOS & MODELAGEM DE DADOS

## 1. Visão Geral da Arquitetura de Dados
A modelagem de dados da aplicação Calistenia Pro foi projetada para suportar um modelo **Client-First / Offline-First** persistido via chave-valor estruturado (`localStorage`) através de um contrato de repositório abstrato (`IStorageRepository`), ao mesmo tempo em que mantém uma estrutura normalizada, estritamente tipada e compatível com migrações para bancos relacionais (PostgreSQL / SQLite) ou orientados a documentos (Firestore / Supabase).

## 2. Dicionário de Tipos Primitivos e Enums

### 2.1 Identificadores de Nível (`LevelId`)
```typescript
enum LevelId {
  LEVEL_1 = 'level_1', // Iniciante Absoluto (Adaptação)
  LEVEL_2 = 'level_2', // Básico Consolidado (Primeiras barras e flexões)
  LEVEL_3 = 'level_3', // Intermediário (Paralelas, força e volume)
  LEVEL_4 = 'level_4', // Avançado (Skills e alavancas)
  LEVEL_5 = 'level_5'  // Atleta de Elite (Planche, Front Lever, Handstand)
}
```

### 2.2 Tipo de Mensuração do Exercício (`ExerciseType`)
```typescript
enum ExerciseType {
  REPETITIONS = 'REPETITIONS', // Movimentos dinâmicos contados por repetições
  TIME = 'TIME'                // Movimentos estáticos/isometrias contados em segundos
}
```

### 2.3 Categorias Musculares (`MuscleCategory`)
```typescript
type MuscleCategory =
  | 'push'      // Empurrar (Peitoral, Deltoide anterior, Tríceps)
  | 'pull'      // Puxar (Dorsal, Bíceps, Romboides, Deltoide posterior)
  | 'legs_core' // Pernas, Abdômen, Lombar
  | 'arms'      // Foco específico em braços
  | 'skills'    // Isometrias e habilidades de calistenia
  | 'fullbody'; // Envolvimento global
```

### 2.4 Status da Sessão de Treino (`SessionStatus`)
```typescript
type SessionStatus = 'COMPLETED' | 'ABANDONED';
```

### 3.7 Sub-Entidades de Sessão: `ExerciseSession` e `SetSession`
Estrutura aninhada que armazena a performance real, série por série.

#### `ExerciseSession`
* `id` (`String`, PK): Identificador do registro do exercício na sessão.
* `exerciseId` (`String`, FK): ID do exercício executado.
* `exerciseName` (`String`): Nome do exercício no momento do treino.
* `type` (`ExerciseType`): Tipo (`REPETITIONS` ou `TIME`).
* `order` (`Integer`): Posição no treino.
* `sets` (`Array<SetSession>`): Lista de séries registradas.

#### `SetSession`
* `id` (`String`, PK): Identificador da série.
* `setNumber` (`Integer`): Número da série (1, 2, 3...).
* `targetRepetitions` (`Integer`, opcional): Meta prevista de repetições.
* `actualRepetitions` (`Integer`, opcional / anulável): Repetições **efetivamente realizadas**.
* `targetDuration` (`Integer`, opcional): Meta prevista de segundos.
* `actualDuration` (`Integer`, opcional / anulável): Segundos **efetivamente sustentados**.
* `completed` (`Boolean`): Indica se a série foi concluída (`true`) ou ignorada (`false`).
* `completedAt` (`String` ISO 8601, opcional): Carimbo de hora exato da conclusão da série.

## 6. Regras de Integridade Referencial e Cascatas

1. **Exclusão de Exercício:**
   * Se um exercício customizado for excluído da biblioteca, as sessões de histórico passadas **mantêm** o snapshot do nome do exercício (`exerciseName`), preservando a integridade histórica.
   * Nas rotinas de treino (`WorkoutExercise`) ativas, se um exercício for removido, o sistema substitui o item pelo exercício padrão disponível ou remove a linha correspondente da rotina.
2. **Exclusão de Treino:**
   * Se um treino for removido ou alterado, a grade semanal (`WorkoutScheduleDay`) que apontava para ele é atualizada para `isRestDay = true` ou aponta para o primeiro treino válido do nível.
3. **Exclusão de Sessão do Histórico:**
   * A exclusão de uma sessão remove a entidade `WorkoutSession` e seus `ExerciseSession` e `SetSession` correspondentes do array de sessões. As métricas agregadas e recordes pessoais (PRs) são recalculados dinamicamente com base nas sessões remanescentes.
4. **Restauração Padrão do Nível:**
   * Ao acionar "Restaurar Grade Padrão", apenas a chave `calistenia_schedules[currentLevelId]` e `calistenia_workouts[currentLevelId]` são restauradas aos valores do `defaultData.ts`. O histórico de sessões do usuário **não** é afetado.

## 7. Estruturas e Algoritmos de Dados Derivados / Calculados

### 7.1 Cálculo de Volume Total Acumulado
* **Repetições Totais:** $\sum (\text{actualRepetitions})$ para todas as séries onde $\text{completed} = \text{true}$ e $\text{actualRepetitions} \neq \text{null}$.
* **Segundos de Isometria Totais:** $\sum (\text{actualDuration})$ para todas as séries onde $\text{completed} = \text{true}$ e $\text{actualDuration} \neq \text{null}$.
* **Minutos em Treino:** $\sum (\lfloor \text{durationSeconds} / 60 \rfloor)$ para todas as sessões do histórico.

### 7.2 Cálculo de Recordes Pessoais (PR - Personal Records)
Para cada `exerciseId` presente no histórico:
$$\text{MaxReps} = \max (\text{actualRepetitions})$$
$$\text{MaxDuration} = \max (\text{actualDuration})$$
O sistema mantém o maior valor unitário realizado em uma única série ao longo de todo o histórico.

### 7.3 Cálculo do Progresso da Sessão em Andamento
$$\text{Progresso} (\%) = \min\left(100, \left\lfloor \frac{\text{Séries Concluídas}}{\text{Total de Séries Previstas no Treino}} \times 100 \right\rfloor\right)$$

## 8. Seed Data (Dados Iniciais Mandatórios)
A aplicação deve ser inicializada com os seguintes dados essenciais no primeiro carregamento:
* **5 Níveis:** Nível 1 (Iniciante Absoluto), Nível 2 (Básico Consolidado), Nível 3 (Intermediário), Nível 4 (Avançado), Nível 5 (Atleta de Elite).
* **Catálogo de 15+ Exercícios:** Variações completas com instruções técnicas, categorias musculares e links de vídeo (ex: Flexão na Parede, Flexão Inclinada, Flexão Padrão, Flexão Diamante, Flexão Arqueiro, Barra Australiana, Barra Fixa Pronada, Dips nas Paralelas, Agachamento Livre, Hollow Body Hold, L-Sit, Straddle Planche, Muscle-up).
* **Rotinas e Grades Semanal Padronizadas:** 3 a 5 dias de treino por nível com dias de descanso intercalados.
